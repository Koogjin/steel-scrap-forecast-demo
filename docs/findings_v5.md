# Demo V5 — 결과와 해석

> 방법론은 실행 **전에** 문서와 설정 파일로 고정(freeze)해 커밋했고, 결과를 본 뒤
> 어떤 설정도 바꾸지 않았습니다. 사전등록 공식 결과와 V2·V3·V4 는 전부 보존됩니다.

**결론을 먼저 씁니다.**

1. **시장 정보 모델(M1) 재설계는 성공했습니다.** 이 프로젝트에서 시장·산업 정보가
   가격 이력을 넘어선 것은 **처음**입니다.
2. **공식 Event 정보는 이번에도 예측 정확도를 개선하지 못했습니다.** 네 개의 정보
   조합 어디에서도, 두 분석 방식 모두에서 개선이 없었습니다.
3. **다만 Event 노이즈 주입은 크게 줄었습니다.** 모델이 스스로 "이번 달은 Event 를
   쓰지 않겠다"고 판단할 수 있게 되었기 때문입니다.

## 1. 2×2 정보 실험 — 이번 단계의 중심 결과

같은 50개 예측 시점 · 같은 학습 데이터 · 같은 대상 월.

### 운영 모델 (실제로 배포 가능한 형태)

| MAE ↓ | Event 없음 | Event 있음 |
|---|---|---|
| **시장 없음** | **M0 49.19** | ME\* 51.86 |
| **시장 있음** | **M1\* 48.83** | M2\* 51.04 |

### 통제 비교 (모형 계열을 고정하고 정보만 늘림)

| MAE ↓ | Event 없음 | Event 있음 |
|---|---|---|
| **시장 없음** | M0 49.19 | ME 50.03 |
| **시장 있음** | **M1 47.14** | M2 52.16 |

### 네 가지 질문에 대한 답

| 질문 | 결과 | 통계 |
|---|---|---|
| 시장 정보가 가격이력을 넘는가 (운영) | **+0.7% 개선** | p = 0.88 |
| 시장 정보가 가격이력을 넘는가 (통제) | **+4.2% 개선** | p = 0.075 |
| Event 가 가격이력을 넘는가 | **−5.4% 악화** | p = 0.25 |
| 시장 위에서 Event 가 더하는가 (통제) | **−10.7% 악화** | **p = 0.019** |

## 2. 무엇이 M1 을 고쳤는가 — 블록 규제

이전 설계는 **하나의 규제 강도**를 모델 전체에 적용했습니다. 그래서 잡음 많은 시장
변수를 억누르려면 **유용한 가격이력 신호까지 함께 눌러야** 했습니다.

V5 는 가격이력·시장·Event 에 **각각 다른 규제 강도**를 적용합니다.

실제로 서로 다른 값이 선택되었습니다.

| 규제 대상 | 선택된 값의 범위 |
|---|---|
| 가격이력 | 1 ~ 10,000 (넓게 분포) |
| 시장 | **10 ~ 100 에만 머묾** |

즉 가격이력을 강하게 규제해야 하는 시점에도 시장 정보는 약하게 유지될 수 있었습니다.
이전 설계에서는 **구조적으로 불가능했던 상태**입니다.

### 선택된 시장 모델

| 방식 | 선택 횟수 |
|---|---|
| **PLS (상관 높은 12개를 소수 요인으로 압축)** | **28 / 50** |
| 가격이력만 사용 (fallback) | 20 / 50 |
| 기타 | 2 / 50 |

**상관이 높은 시장 변수를 소수 요인으로 압축하는 접근이 이 표본 크기에 맞았습니다.**

### 정직한 트레이드오프

| | MAE |
|---|---|
| 통제 비교 M1 (잡음 방어 끔) | **47.14** |
| 운영 M1\* (잡음 방어 켬) | 48.83 |

잡음 방어 문턱이 20/50 시점에서 가격이력 모델로 되돌리게 했고, 그만큼 **진짜 시장
신호도 함께 막혔습니다.** 두 숫자를 함께 보아야 합니다.

## 3. Event 는 왜 여전히 도움이 안 되는가

### 모델이 스스로 Event 를 거의 쓰지 않기로 했다

| | 값 |
|---|---|
| Event 를 쓰지 않은 예측시점 | **90%** |
| 중앙값 보정폭 | **0.0** 지수 Point |
| 평균 보정폭 | 4.7 지수 Point |

**이것이 V4 와 결정적으로 다른 점입니다.** V4 에서는 Event 가 모든 시점에서 강제로
사용되어 중앙값 15 지수 Point 씩 예측을 흔들었습니다.

### 그런데도 나빠진 이유 — 쓴 소수의 달이 무너졌다

| Event 사용 여부 | 시점 수 | 시장 모델 MAE | Event 추가 후 MAE |
|---|---|---|---|
| **사용함** | 5 | **43.47** | **65.61** |
| 사용 안 함 | 45 | 49.42 | 49.42 |

Event 가 쓰인 5개 시점은 **원래 시장 모델이 가장 잘 맞히던 달**이었는데, Event 를
반영하자 오차가 크게 벌어졌습니다.

### 새로운 Event 정보(Novel)는 학습 안에서 압도적으로 선호되었다

Event 정보 중 "최근 가격과 시장 지표로 이미 설명되는 부분"을 제거한 표현을 후보로
넣었습니다. **Event 가 선택된 모든 경우에 이 Novel 표현이 뽑혔고, 원본은 한 번도
선택되지 않았습니다.**

**그럼에도 예측 정확도는 개선되지 않았습니다.** 직교화는 신호를 더 깨끗하게 만들었지만,
남은 성분에 예측력이 있다는 증거는 나오지 않았습니다.

### 어떤 Event 채널이 유용한지는 판별할 수 없다

| 채널 | 활성 월 |
|---|---|
| 철강·무역 정책 | 50 / 50 (항상 활성) |
| 지정학·공급 | 50 / 50 (항상 활성) |
| 수요·거시 충격 | **2 / 50** |

앞의 두 채널은 평가 구간 내내 활성이라 "활성 월 vs 비활성 월" 비교가 성립하지 않고,
세 번째는 활성이 2개월뿐입니다. **월을 채우려고 사건을 만들지 않았습니다.**

## 4. V4 대비 무엇이 나아졌는가

| | V4 | **V5** |
|---|---|---|
| 시장 모델 최고 | 60.99 | **47.14** |
| Event 모델 | 67.40 | **51.04** |
| Event 중앙값 보정폭 | 15.17 | **0.00** |
| Event 사용 비율 | 100% (강제) | **10%** (선택) |

Event 모델의 개선(+24.3%, p = 0.010)은 V5 에서 통계적으로 가장 뚜렷합니다.
다만 이것은 **V4 의 실패를 되돌린 것**이지 Event 가 유용해진 것이 아닙니다.

## 5. 가장 큰 남은 한계 — 표본 크기, 그리고 그 구체적 형태

V5 는 이 한계의 **정확한 메커니즘**을 처음으로 드러냈습니다.

예측 시점마다 후보 모델이 수백~수천 개인데, 내부 검증에 쓸 수 있는 달은 **36개뿐**
입니다. 예측 대상과 **아무 관계가 없는 난수**를 넣고 시험한 결과:

| 층 | 우연히 얻은 '개선' 중앙값 | 최대 |
|---|---|---|
| 시장 | 1.6% | 8.4% |
| Event | 5.6% | 11.9% |

즉 이 규모에서는 **모델 선택 자체가 과적합의 주된 원천**입니다. 그래서 12% 문턱을
두었고, 그 문턱이 다시 진짜 시장 신호도 일부 막았습니다.

**새 변수나 새 모델이 아니라, 더 긴 과거 이력만이 이 딜레마를 풉니다.**

---

## 6. 경영진 보고용 한 줄

> 시장·산업 정보를 제대로 결합하면 과거 가격만 쓰는 모델보다 나아질 수 있다는
> 근거가 처음으로 나왔습니다. 다만 그 차이는 아직 통계적으로 확실하지 않고,
> 공식 Event 정보는 현재 표본에서 예측 정확도를 높이지 못했습니다.

## 7. 하지 않은 것

- 다음 버전을 시작하지 않았습니다.
- 새 외부 데이터를 추가하지 않았습니다.
- 결과를 본 뒤 Event 기록·채널 분류·신뢰도 격자를 바꾸지 않았습니다.
- 과거의 부정적 결과를 지우지 않았습니다.
