# 방법론 요약

## 1. Point-in-Time (PIT) 재구성

경제지표는 최초 발표 후 여러 차례 개정됩니다. 과거를 모델링할 때 **현재의 최종
수정값**을 쓰면 그 시점에 알 수 없었던 정보가 모델에 들어갑니다.

이 프로젝트는 US BLS 와 Federal Reserve 의 **당시 historical release 원문**을 직접
수집·파싱해, 관측월 × 발표일 단위의 패널을 만들었습니다.

```
forecast origin O 에서 사용 가능한 값
  = release_date <= O 인 발표분 중 가장 최근 값
```

같은 관측월이라도 origin 이 다르면 값이 다를 수 있으며, 패널은 그 차이를 보존합니다.

## 2. 데이터

| 구분 | 계열 | 원기관 / 발간물 |
|---|---|---|
| 예측 대상 | **WPU1012** (Iron and steel scrap, 상품코드 10-12, 비계절조정) | US BLS · PPI Detailed Report |
| 강건성 대상 | WPU101211 | US BLS · PPI Detailed Report |
| 설명변수 | WPU1017, WPU0542 | US BLS · PPI Detailed Report Table 9 |
| 설명변수 | AWHMAN | US BLS · Employment Situation Table B-7 |
| 설명변수 | INDPRO, IPG331S, CAPUTLG331S | Federal Reserve · G.17 |

계열당 파생 2개(수준 + 3개월 변화) = **12개 설명변수**.
상호작용항·다항확장·자동 변수선택·PCA 를 쓰지 않습니다.

`CPIAUCSL` 은 과거 구간은 완성됐지만 **매월 갱신 경로가 없어** 공식 운영 세트에서
제외하고 별도의 historical robustness 로만 둡니다. 이 판단은 예측 성능이 아니라
운영 재현성·취득 지속성·출처·시점 신뢰도 기준입니다.

## 3. 평가 설계 (사전등록)

- 예측 시계: 월말 시점 → 다음 달 (1개월)
- 평가 시점: 50개 (2021-11-30 ~ 2025-12-31)
- 최소 학습 지지: 72행 (내부 CV 3-fold × 12개월 검증 블록)
- 모델: **Ridge 단일** (모델 쇼핑 방지)
- 초매개변수: 고정 alpha 금지, 각 시점의 **학습 데이터 안에서만** 시간순 중첩 CV 로 선택
- 전처리: 결측대치·표준화를 각 fold 학습행에만 적합
- 주 지표: **MAE** 하나. RMSE/sMAPE/방향정확도는 기술 통계
- 검정: Diebold-Mariano (HLN 소표본 보정) + moving-block bootstrap 신뢰구간

## 4. 사건 압력 (탐색적)

뉴스 기사 본문을 수집하지 않습니다. 대신 **공식 기관이 발표한 사실**만 구조화합니다.

- PEP = 가격 **상승** 압력 증거, NEP = 가격 **하락** 압력 증거
- 감성분석이 아니며 두 지표는 독립 (합이 1이 아님)
- 기여도 0~3, 감쇠 1.00 / 0.50 / 0.25 / 0 — 결과를 보기 전에 고정
- 대상월 m 의 압력은 **m 이 시작되기 전에 알려진 사건**만 사용

## 5. 한계

- 평가 시점이 50개로 검정력이 제한적입니다. "유의하지 않음"과 "효과 없음"은 다릅니다.
- Clean-PIT 대상 패널의 관측월이 137개뿐이라 학습 구간이 짧습니다.
- 설명변수가 미국 공급·산업활동 축에 치우쳐 있고, 원자재 가격·전방 수요 축이 비어 있습니다.
- M2(사건 압력)는 탐색적이며, 관측된 성능 저하는 사건의 정보가치가 아니라
  변수 지지 구간 문제에서 비롯됐습니다.

# Demo V2 추가 사항 (탐색적 확장)

사전등록된 official 실험(N0/M0/M1)은 **그대로 보존**된다. 아래는 별도 확장이다.

## 6. Common support — 동일 Train/Test

각 예측시점에서 M0/M1/M2 가 쓸 수 있는 학습 행의 **교집합**을 먼저 계산하고, 세 단계
모두 그 행만 쓴다. 어느 한 단계에서 결측인 행은 **세 단계 모두에서** 제외한다.

그래서 "M0 는 100행, M2 는 74행" 같은 불공정 비교가 원천적으로 불가능하다.
예측 시점·대상 월·평가 지표도 전부 동일하다.

## 7. 두 가지 비교 방식

| view | 목적 | 방법 |
|---|---|---|
| **A. 통제 비교** | 정보를 추가하면 성능이 어떻게 변하는가 | 알고리즘을 Ridge 로 고정 |
| **B. Best-CV 벤치마크** | 각 정보 집합에서 가장 적합한 모델을 고르면 어떻게 되는가 | 학습 데이터 안에서만 model family 선택 |

후보: Ridge · ElasticNet · RandomForest · HistGradientBoosting (전부 무료 CPU
sklearn). 딥러닝을 쓰지 않는다.

**모델 선택은 각 예측시점의 과거 학습데이터 내부 시간순 CV 로만 한다.**
최종 OOS test 월은 모델 선택에 참여하지 않는다. M0/M1/M2 에 **동일한 후보군과
동일한 CV 예산**을 적용한다. 초매개변수 grid 는 OOS 를 보기 전에 고정했다.

## 8. 사건 압력 V2

`docs/event_method.md` 참조. 요점:

- POINT 사건 + **ONGOING 상태** 구분 → 긴 이력에서 support 유지
- 카테고리별 월 상태를 **최댓값으로 상한** → 사건 개수가 신호를 지배하지 못함
- `PEP, NEP ∈ [0,1]` → **표준화하지 않음** (z-score 폭발 불가능)
- 대상월 m 의 상태는 m 시작 전에 알려진 것만 사용

# Demo V3 추가 사항 (탐색적 확장)

사전등록된 official 실험(N0/M0/M1)과 Demo V2 산출물은 **그대로 보존**된다.

## 9. 네 단계 common support

`M0 / M1 / M2-V2 / M2-V3` 가 완전히 같은 예측시점·학습행·대상월·지표를 쓴다.
어느 한 단계에서 결측인 행은 **네 단계 모두에서** 제외한다.

M2-V2 와 M2-V3 는 **변수 개수가 2개로 같다.** 그래야 차이를 "변수를 더 넣어서"가
아니라 **"같은 개수의 변수를 다르게 정의해서"** 라고 말할 수 있다.

V3 에서 **새 모델 계열을 추가하지 않았다** — Best-CV 후보군은 Demo V2 와 동일하다.

## 10. 사건 압력 V3

`docs/event_method_v3.md` 참조. 요점:

- 사건을 **사안(episode) + 상태 변화(transition)** 두 층으로 기록
- 각 상태를 **직접성 · 범위 · 확실성**으로 채점 (확실성은 단계로부터 자동 결정)
- 시간이 지나면 **감쇠 + 잔존 하한** — 오래된 조치는 압력이 아니라 baseline
- 사안 안에서는 최댓값(중복 통제), 분류 안에서도 최댓값(같은 채널),
  분류 사이에서만 독립 증거로 결합 → 빈 분류가 신호를 희석하지 않음
- `PEP, NEP ∈ [0,1]` → **표준화하지 않음**
- 채점 규칙과 사건 목록을 **예측을 한 번도 실행하기 전에** 고정

## 11. 사건 기여 진단

`M2 − M1` 은 두 경로가 섞인 값이므로 counterfactual 로 분해한다.

```
직접  =  M2 예측  −  M2 예측(사건 변수를 0 으로)
간접  =  M2 예측(사건=0)  −  M1 예측
```

간접 경로는 변수가 2개 늘면서 나머지 모든 계수가 다시 적합되고, 교차검증이 다른
정규화 강도를 고르는 데서 나온다.

**측정 결과 두 효과가 비슷한 크기로 서로 상쇄되고 있었다.** 그래서 현재 설계로는
관측된 `M2 − M1` 차이를 사건 정보의 효과라고 부를 수 없다. 다음 사전등록에서
정규화 강도를 단계 간에 고정해 이 교란을 제거한다.

## 12. 결과 (있는 그대로)

사건 압력은 M1 을 개선하지 못했고 M1 도 M0 를 개선하지 못했다. 어느 비교도
통계적으로 유의하지 않다. 이 조건에서 가장 정확한 것은 여전히 M0 다.
`docs/findings_v3.md` 참조.

## 13. Demo V4 — Staged Residual Architecture

방법론은 실행 **전에** 설정 파일과 문서로 고정해 커밋했고,
실행은 **정확히 한 번**이다. 결과를 본 뒤 어떤 설정도 바꾸지 않았다.

### 13-1. 구조

```
M0            base layer (공식 M0 와 동일 규칙 · 예측값도 일치)
M1-R = M0   + market correction    (기존 12개 파생 시장 변수만)
M2-R = M1-R + event correction     (V3 PEP/NEP · 정의 불변)
```

**`M2-R − M1-R` 은 정의상 정확히 Event 보정폭이다.** 자동 테스트가 모든 예측
시점에서 이 항등식을 강제한다. 규제 재선택·전체 계수 재적합이 끼어들 자리가 없다.

### 13-2. Prequential 잔차 — in-sample 잔차 금지

보정 층의 학습 target 은 historically valid 해야 한다. 전체 학습행에 적합한 뒤 얻은
잔차를 쓰면 **실제 예측 시점에 관측 불가능한 값**을 배우게 된다.

각 예측 시점의 학습 구간 **안에서** expanding block 으로 만든다.

```
행: 대상월 오름차순 0 .. N
|<-- 초기 24행 -->|[ 6 ][ 6 ][ 6 ] ...
블록 [s,e):  [0,s) 에 적합 -> [s,e) 예측 -> 잔차
```

전처리(결측 대체·표준화)도 **각 블록의 적합 구간에만** fit 한다.
학습행 72 에서 base 잔차 48행 / event 잔차 24행, 118 에서 94행 / 70행이 나온다.

**명시적 한계.** 블록 재적합은 계수만 다시 추정하고 규제 강도·모델 family·성분 수는
그 시점의 학습 전체에서 고른 값을 쓴다. 블록 하나로는 내부 교차검증을 다시 만들 수
없기 때문이다. 모든 값이 `release_date <= O` 안에 있으므로 누수는 아니지만,
학습 구간 내부의 완벽한 실시간 모사도 아니다.

### 13-3. 후보 집합 (실행 전 동결)

| 층 | 후보 |
|---|---|
| Market correction | Ridge(6 alpha) · ElasticNet(4 alpha, l1=0.5) · **PLS(1~4 성분)** · Bayesian Ridge |
| Event feature | **E0** 수준 · **E1** 수준+변화 · **E2** 수준+1개월 lag |
| Event correction | OLS · Ridge(6 alpha) · Huber(ε=1.35) |

부호 제약 모델은 **도입하지 않았다** — 사전 신념을 모델에 넣는 것이 이번 단계의
질문과 어긋나기 때문이며, 이 결정은 성능을 보기 전에 내렸다.

선택은 전부 **학습 데이터 내부 시간순 교차검증**으로만 하고, 최종 Test 월은
어떤 선택에도 참여하지 않는다.

### 13-4. VIEW C — shared-alpha 대조

규제 재선택 교란을 제거한 joint Ridge 대조군. 예측 시점마다 **M1 학습에서 고른
규제 강도**를 구하고 그 **같은 값**을 M1 과 M2 양쪽에 적용한다.
따라서 `M1-shared` 는 공식 M1 과 일치한다.

### 13-5. 결과 (있는 그대로)

| 모델 | MAE |
|---|---|
| M0 | **49.19** |
| M1 | 50.75 |
| M2-V2 / M2-V3 | 50.72 / 51.61 |
| M1-shared / M2-shared | 50.75 / **50.90** |
| M1-R / M2-R | 60.99 / 67.40 |

- **V3 악화의 약 83% 는 Event 정보가 아니라 규제 재선택·재적합 교란이었다.**
  규제를 고정하면 Event 추가 비용은 MAE +0.149 로 통계적으로 구분되지 않는다.
- 단계 구조에서 Event 보정폭은 중앙값 0.20 → **15.17** 로 커졌다(|보정|>5 인 시점
  80%). **규제가 Event 신호를 억누르고 있었던 것은 사실이다** — 유계 변수는 같은
  기여를 만들려면 계수가 4.6배 커야 하고 벌점은 21배를 치른다(측정값).
- 그러나 방향 적중률은 **54%**, MAE 는 **+6.41** 악화됐다. 큰 보정 × 무작위 방향은
  분산 주입이다.
- 실패 원인(측정): prequential base 잔차 MAE **59.64** vs 최종 M0 실제 오차 **49.19**.
  보정 층이 약한 모델의 잔차 크기를 배워 강한 모델 위에 얹는다. 시장 보정은 오차의
  83% 크기인데 부호 적중은 42% 로 동전 던지기보다 나쁘다.

`docs/findings_v4.md` 참조. **가장 큰 남은 제약은 모델이 아니라 표본 크기다.**

## 14. Demo V5 — M2 중심 재설계 + 2×2 정보 실험

방법론은 실행 **전에** 설정 파일과 문서로 고정해 커밋했고, 결과를 본 뒤 어떤 설정도
바꾸지 않았다.

### 14-1. 블록 규제 (M1 을 고친 것)

전역 penalty 하나 대신 블록마다 다른 penalty 를 준다.

```
min  ||y - Zb||^2 + a_H||b_H||^2 + a_X||b_X||^2 + a_E||b_E||^2
```

표준화를 **적합 안에서 학습행 통계로만** 하므로 penalty 가 원 단위에 의존하지 않는다
(scale-invariant, 테스트가 강제).

실측: `a_X` 를 1 → 10,000 으로 올리면 Market 계수 norm 은 0.307 → 0.002 로 수축하는데
History 계수 norm 은 9.643 → 9.655 로 **사실상 불변**이다. V4 의 실패 모드가 구조적으로
제거된다.

M1 후보 246개 = M0 fallback + block + PLS(1~4 성분) + convex combination(w 0~1).
`gamma_X ∈ {0,.25,.5,.75,1}` 로 Market 신뢰도를 학습 안에서 조정한다.

**V5 의 History-only 모델은 공식 M0 를 수치적으로 재현한다**(max |차이| 6.8e-13,
50 origin 전부 같은 alpha) — 2×2 가 공식 결과에 고정된다.

### 14-2. Event 표현 (M2 의 본체)

- **State** `PEP`, `NEP` — 지금 어떤 압력 환경인가
- **Shock** `ΔPEP`, `ΔNEP` — 이번 달에 무엇이 새로 바뀌었나
- **거시 채널** — 동결된 V3 카테고리 7개를 빠짐없이·중복없이 3개로 매핑하고
  채널별 순압력 변화를 만든다(target 미사용, 실행 전 동결)
- **Event family 4개** — E0 state · E1 state+shock · E2 +lag1 · E3 +channel shock
- **Novel Event** — Event 를 History(+Market)로 예측한 뒤 뺀 나머지.
  **target 잔차 적합이 아니라 Event 직교화**이며 WPU1012 를 전혀 쓰지 않는다.
  학습행은 expanding block cross-fitting, live 행은 학습행 전체로만 적합.

### 14-3. Event 신뢰도와 NO_EVENT

```
M2* = Base + lambda_E * (EventEnhanced - Base)     lambda_E ∈ {0,.25,.5,.75,1}
```

`EventEnhanced - Base` 는 **같은 블록 penalty 아래의 no-event 쌍둥이**와의 차이로
계산한다 — V3 가 실패한 지점(규제 재선택·전체 refit 혼입)을 구조적으로 막는다.
`lambda_E = 0` 이 격자에 있으므로 **NO_EVENT 가 언제나 후보다.**

### 14-4. parsimony margin 0.12 — 합성 null 보정

origin 하나마다 후보가 수백~수천 개인데 inner 검증행은 3 fold × 12개월 = 36개뿐이다.
**난수 40회 시뮬레이션**(WPU1012·Market X·Event 레지스트리 미사용) 결과 우연한 개선은

    market  median 1.57% · p90 6.72% · max  8.38%
    event   median 5.58% · p90 11.07% · max 11.93%

이고 margin 0.12 에서 두 층 모두 fallback 유지율 100% 가 된다. 그래서 확장 정보는
fallback 보다 inner-CV MAE 를 **12% 이상** 낮출 때에만 선택된다.

**대가를 명시한다** — 이 문턱은 약한 진짜 신호도 함께 막을 수 있다. 그래서 controlled
track 은 margin 없이 정보 증분을 그대로 보여준다.

### 14-5. 2×2 정보 실험과 두 트랙

| | Event 없음 | Event 있음 |
|---|---|---|
| Market 없음 | M0 | ME* |
| Market 있음 | M1* | M2* |

- **CONTROLLED** — 네 셀에 같은 블록 Ridge, Event 표현 `E1`/`RAW` 고정, 보정 없음
- **OPERATIONAL** — 학습 전용 선택 + `gamma_X`·`lambda_E` 보정 (주 성능 결과)

`ME*` 는 필수다 — 현재 M1 이 M0 보다 약했으므로 Event 는 M0 위에서 더 잘 작동할 수
있고, ME* 만 개선되면 Market X 가 Event 증분정보를 가린다는 뜻이다.

### 14-6. 결과 (있는 그대로)

| MAE ↓ | Event 없음 | Event 있음 |
|---|---|---|
| **OPERATIONAL** Market 없음 | 49.19 | 51.86 |
| **OPERATIONAL** Market 있음 | **48.83** | 51.04 |
| **CONTROLLED** Market 없음 | 49.19 | 50.03 |
| **CONTROLLED** Market 있음 | **47.14** | 52.16 |

- **M1 재설계 성공** — controlled M1 47.14 는 M0 49.19 를 4.17% 개선(DM p=0.075).
  이 프로젝트에서 시장 정보가 가격이력을 넘어선 것은 처음이다.
  선택 분포: PLS 28/50 · M0-fallback 20/50.
- **Event 는 여전히 개선하지 못한다** — 네 셀·두 트랙 모두. 가장 뚜렷한 것은
  controlled M1 → M2 −10.7% (DM p=0.019).
- **Event 노이즈는 크게 줄었다** — V4 M2-R 67.40 → V5 M2* 51.04 (+24.3%, DM p=0.010).
  NO_EVENT fallback 90%, median 보정폭 0.00.
- **Novel Event 는 학습 안에서 RAW 를 100% 이겼다**(M2 5/5, ME 19/19). OOS 개선은 없다.
- **채널별 유용성은 판별 불가** — 두 채널이 50개월 내내 활성, 나머지 하나는 2개월.

`docs/findings_v5.md` 참조. **가장 큰 남은 제약은 표본 크기이며, V5 는 그 제약이
'모델 선택 과적합'이라는 구체적 형태로 나타남을 처음 정량화했다.**

## 15. Demo V6 — Event 예측역할 연구 (탐색적)

**동결 후 실행.** 결과를 본 뒤 라벨·임계값·예측기간·후보군을 고치지 않았다.

### 15-1. 왜

V1~V5 는 "Event 가 다음 달 **지수 수준**을 더 잘 맞히는가"를 충분히 조사했고 답은
일관되게 아니오였다. V6 는 그 답을 뒤집으려는 것이 아니라 **다른 질문**을 새로
사전등록했다 — Event 가 **방향 / 큰 변동 / 전환점** 에는 정보를 담고 있는가.

### 15-2. 설계

- **새 아이디어 정확히 2개** — Transition Impulse(상태 변화 그 자체), Freshness(신선도).
- **Feature family 정확히 2개** — EV-F0(둘 다 없음) / EV-F1(둘 다 포함).
- **모형 계열 1개** — 블록 규제 로지스틱. model zoo 금지.
- **2×2** (D0 / D1 / DE / D2) × **역할 3개** × **예측기간 3개**.
- **예측기간 위계 동결** — 1개월이 PRIMARY, 2·3개월은 확인용.
- **최소 지지 규칙** — 양성·음성 각 10건 미만이면 `UNDERPOWERED` 로 판정 유보.

### 15-3. 결과 (있는 그대로)

| 예측 역할 (1개월) | Event 를 더했을 때 | 판정 |
|---|---|---|
| 지수 수준 (V5 동결) | MAE 48.83 → 51.04 | 악화 |
| 방향 | Balanced Accuracy −0.036 (p = 0.430) | 악화 |
| 큰 변동 | PR-AUC −0.035 (p = 0.372) | 악화 |
| 전환점 | Balanced Accuracy −0.059 (p = 0.343) | 악화 |

**이번 단계에서 처음으로 이유가 보였다.** 학습 내부검증 정확도와 실제 예측 정확도의
격차가 **시장 정보만 쓴 모델은 사실상 0**(−0.003)인 반면 **Event 를 포함한 모델만
+0.068 ~ +0.237** 이었다. 즉 Event 는 과거 데이터에 맞출 때는 유용해 보이지만 실제
예측에서 그 유용성이 재현되지 않는다.

`docs/findings_v6.md` 참조.

## 16. Demo V7 — Event 위험 · 조건부 가치 (탐색적)

**동결 후 실행** (`V7A-2026-08-27`). 결과를 본 뒤 구간 수준·tail 임계값·상호작용
짝·모형 계열을 고치지 않았다.

### 16-1. 왜

정확도 질문의 답이 여덟 번 연속 아니오였다. V7 은 경영 현장이 실제로 쓰는 것 —
**"얼마나 틀릴 수 있는가"** — 를 묻는다. 점 예측 모델(M1\*)은 **V5 산출물을 그대로**
쓰고 재설계하지 않는다. V7 이 다루는 것은 그 주변의 불확실성뿐이다.

### 16-2. 네 개의 Track (사전등록)

| Track | 질문 | 지표 | 지위 |
|---|---|---|---|
| **A** | Event 조건부 불확실성이 80% 구간을 개선하는가 | Interval Score ↓ | **PRIMARY** |
| B | Event 가 급등·급락(상·하위 20%) 위험을 감지하는가 | Brier ↓ | 보조 |
| C | Event 효과가 시장 상황에 따라 달라지는가 | MAE ↓ | 보조 |
| D | 발표창 신규 Event 가 지속형 표현보다 유용한가 | MAE ↓ | 보조 |

- **후보 총량 45개**로 사전 제한. 새 raw X 없음. 새 사건 기록 없음. 새 분류 없음.
- Track A 는 **scale-conformal** — `interval = M1* ± q·scale(Event)`, `q` 는 학습
  전용 conformal 분위수. 미래 잔차로 보정하지 않는다.
- Track B 임계값은 **학습 구간 prequential 잔차 분위수**에서만 정한다.
- Track C 는 **정확히 3개**의 상호작용만 사전 선언한다
  (무역정책×가동률 · 지정학×전력비용 · 수요거시×산업생산).
- Track C/D 는 **통제 트랙** — `alpha_H`/`alpha_X` 를 M1-CTRL 에서 물려받고
  `alpha_E` 만 선택한다. 재적합 교란을 막기 위한 V4 이후의 표준 절차다.
- 평가 표본이 다르다는 사실을 그대로 보고한다 — Track A/B 는 37 origin
  (prequential 오차 12개 이상 축적 후), Track C/D 는 50 origin.

### 16-3. 결과 (있는 그대로)

| Track | 비교 | 지표 | 결과 | p |
|---|---|---|---|---|
| **A (PRIMARY)** | U0 → U1 | Interval Score | 258.27 → 229.22 | 0.318 |
| B 상단 | T0 → T1 | Brier | 0.159 → 0.218 | 0.324 |
| B 하단 | T0 → T1 | Brier | 0.031 → 0.037 | 0.003 |
| C | M1-CTRL → M2-INT | MAE | 47.14 → 46.27 | 0.354 |
| D 지속형 | M1-CTRL → M2-PERSIST | MAE | 47.14 → 48.43 | 0.769 |
| D 발표창 | M1-CTRL → M2-RW | MAE | 47.14 → 48.96 | **0.00005** |

**1차 가설 지지 안 됨.** 강한 보조 근거 0건이며, 유의하게 나온 두 결과는 **모두 악화
방향**이다.

### 16-4. 이번 실행의 진짜 발견 — 오차 분포의 비정상성

목표 80% 인데 **두 구간 모두 실제 커버리지가 1.000** 이었다. 37개 시점 중 실제값이
구간을 벗어난 경우가 한 번도 없다.

구간 폭은 과거 예측오차 분포에서 나오는데, 그 과거에는 2021~2022년의 격변기가
들어 있고 평가 구간(2023~2025)은 훨씬 잔잔했다. 즉 **오차 분포 자체가 시간에 따라
변했다.** 따라서 Track A 의 비교는 "잘 보정된 두 구간 중 어느 쪽이 나은가"가 아니라
**"둘 다 지나치게 넓은 것 중 어느 쪽이 덜 넓은가"** 다. 과장하지 않고 그대로 적는다.

같은 이유가 Track B 의 표본 부족(급등 4건 / 급락 1건, 규칙은 각 10건)도 설명한다.

### 16-5. 지표 방향 판정기 (V7 hotfix)

V6 대시보드가 `MAE 48.83 → 51.04` 를 "개선"으로 표시하는 버그가 있었다. 원인은
계산이 아니라 **설계** — 부호가 이미 정해진 차이값을 호출부가 넘기는 구조였다.

**공통 지표 방향 판정기** 하나로 대체했다.

- 입력은 **`(지표 이름, baseline 값, new 값)`** 뿐이다. 부호 있는 차이를 받지 않는다.
- 지표 방향은 모듈이 소유한다 (MAE·Brier·Interval Score ↓ / Balanced Accuracy·PR-AUC ↑).
- 모르는 지표는 **KeyError 로 실패**한다 (fail-closed).
- **p 값을 인자로 받지 않는다** — 유의성이 서술적 방향을 뒤집을 수 없다.

화면의 모든 상태 라벨이 이 단일 출처를 쓴다. 테스트가 앱 소스를 스캔해 손으로 적은
라벨이 남지 않았음을 강제한다.

### 16-6. 중단 규칙

실행 **전에** 다음을 적어 두었다.

> 1차 가설이 지지되지 않고 보조 가설에서도 일관된 강한 근거가 나오지 않으면
> **Event 모델 개발을 중단한다.** V8 을 시작하지 않고, 새 Event feature·모형 계열·
> 사건 기록을 추가하지 않는다.

조건이 충족되어 규칙대로 멈춘다. 다음 단계는 **더 긴 Point-in-Time 이력 확보**이며
계획서만 준비했다 (`docs/next_phase_plan.md`, 실행 없음).

### 16-7. 실행 중 고친 것

첫 실행에서 Track C 의 상호작용 값이 예측 시점 행에서 전부 결측이었다. 학습행만 담은
시장 프레임에 예측 시점 행을 reindex 한 **구현 결함**이다. 동결 사양(표준화 통계는
학습 구간에서만)은 그대로 두고 결함만 고쳐 재실행했다. **Track A·B·D 수치가 두
실행에서 완전히 동일**하다 — 수정이 깨진 경로만 건드렸다는 직접 증거다.

`docs/findings_v7.md` 참조.
