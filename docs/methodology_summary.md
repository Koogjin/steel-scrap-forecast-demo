# 방법론 요약

## 1. Point-in-Time (PIT) 재구성

경제지표는 최초 발표 후 여러 차례 개정됩니다. 과거를 모델링할 때 **현재의 최종
수정값**을 쓰면 그 시점에 알 수 없었던 정보가 모델에 들어갑니다.

이 프로젝트는 US BLS 와 Federal Reserve 의 **당시 historical release 원문**을 직접
수집·파싱해, 관측월 × 발표일 단위의 패널을 만들었습니다.

```
forecast origin O 에서 사용 가능한 값
  = release_date <= O 인 발표분 중 가장 최근 값
```

같은 관측월이라도 origin 이 다르면 값이 다를 수 있으며, 패널은 그 차이를 보존합니다.

## 2. 데이터

| 구분 | 계열 | 원기관 / 발간물 |
|---|---|---|
| 예측 대상 | **WPU1012** (Iron and steel scrap, 상품코드 10-12, 비계절조정) | US BLS · PPI Detailed Report |
| 강건성 대상 | WPU101211 | US BLS · PPI Detailed Report |
| 설명변수 | WPU1017, WPU0542 | US BLS · PPI Detailed Report Table 9 |
| 설명변수 | AWHMAN | US BLS · Employment Situation Table B-7 |
| 설명변수 | INDPRO, IPG331S, CAPUTLG331S | Federal Reserve · G.17 |

계열당 파생 2개(수준 + 3개월 변화) = **12개 설명변수**.
상호작용항·다항확장·자동 변수선택·PCA 를 쓰지 않습니다.

`CPIAUCSL` 은 과거 구간은 완성됐지만 **매월 갱신 경로가 없어** 공식 운영 세트에서
제외하고 별도의 historical robustness 로만 둡니다. 이 판단은 예측 성능이 아니라
운영 재현성·취득 지속성·출처·시점 신뢰도 기준입니다.

## 3. 평가 설계 (사전등록)

- 예측 시계: 월말 시점 → 다음 달 (1개월)
- 평가 시점: 50개 (2021-11-30 ~ 2025-12-31)
- 최소 학습 지지: 72행 (내부 CV 3-fold × 12개월 검증 블록)
- 모델: **Ridge 단일** (모델 쇼핑 방지)
- 초매개변수: 고정 alpha 금지, 각 시점의 **학습 데이터 안에서만** 시간순 중첩 CV 로 선택
- 전처리: 결측대치·표준화를 각 fold 학습행에만 적합
- 주 지표: **MAE** 하나. RMSE/sMAPE/방향정확도는 기술 통계
- 검정: Diebold-Mariano (HLN 소표본 보정) + moving-block bootstrap 신뢰구간

## 4. 사건 압력 (탐색적)

뉴스 기사 본문을 수집하지 않습니다. 대신 **공식 기관이 발표한 사실**만 구조화합니다.

- PEP = 가격 **상승** 압력 증거, NEP = 가격 **하락** 압력 증거
- 감성분석이 아니며 두 지표는 독립 (합이 1이 아님)
- 기여도 0~3, 감쇠 1.00 / 0.50 / 0.25 / 0 — 결과를 보기 전에 고정
- 대상월 m 의 압력은 **m 이 시작되기 전에 알려진 사건**만 사용

## 5. 한계

- 평가 시점이 50개로 검정력이 제한적입니다. "유의하지 않음"과 "효과 없음"은 다릅니다.
- Clean-PIT 대상 패널의 관측월이 137개뿐이라 학습 구간이 짧습니다.
- 설명변수가 미국 공급·산업활동 축에 치우쳐 있고, 원자재 가격·전방 수요 축이 비어 있습니다.
- M2(사건 압력)는 탐색적이며, 관측된 성능 저하는 사건의 정보가치가 아니라
  변수 지지 구간 문제에서 비롯됐습니다.

# Demo V2 추가 사항 (탐색적 확장)

사전등록된 official 실험(N0/M0/M1)은 **그대로 보존**된다. 아래는 별도 확장이다.

## 6. Common support — 동일 Train/Test

각 예측시점에서 M0/M1/M2 가 쓸 수 있는 학습 행의 **교집합**을 먼저 계산하고, 세 단계
모두 그 행만 쓴다. 어느 한 단계에서 결측인 행은 **세 단계 모두에서** 제외한다.

그래서 "M0 는 100행, M2 는 74행" 같은 불공정 비교가 원천적으로 불가능하다.
예측 시점·대상 월·평가 지표도 전부 동일하다.

## 7. 두 가지 비교 방식

| view | 목적 | 방법 |
|---|---|---|
| **A. 통제 비교** | 정보를 추가하면 성능이 어떻게 변하는가 | 알고리즘을 Ridge 로 고정 |
| **B. Best-CV 벤치마크** | 각 정보 집합에서 가장 적합한 모델을 고르면 어떻게 되는가 | 학습 데이터 안에서만 model family 선택 |

후보: Ridge · ElasticNet · RandomForest · HistGradientBoosting (전부 무료 CPU
sklearn). 딥러닝을 쓰지 않는다.

**모델 선택은 각 예측시점의 과거 학습데이터 내부 시간순 CV 로만 한다.**
최종 OOS test 월은 모델 선택에 참여하지 않는다. M0/M1/M2 에 **동일한 후보군과
동일한 CV 예산**을 적용한다. 초매개변수 grid 는 OOS 를 보기 전에 고정했다.

## 8. 사건 압력 V2

`docs/event_method.md` 참조. 요점:

- POINT 사건 + **ONGOING 상태** 구분 → 긴 이력에서 support 유지
- 카테고리별 월 상태를 **최댓값으로 상한** → 사건 개수가 신호를 지배하지 못함
- `PEP, NEP ∈ [0,1]` → **표준화하지 않음** (z-score 폭발 불가능)
- 대상월 m 의 상태는 m 시작 전에 알려진 것만 사용

# Demo V3 추가 사항 (탐색적 확장)

사전등록된 official 실험(N0/M0/M1)과 Demo V2 산출물은 **그대로 보존**된다.

## 9. 네 단계 common support

`M0 / M1 / M2-V2 / M2-V3` 가 완전히 같은 예측시점·학습행·대상월·지표를 쓴다.
어느 한 단계에서 결측인 행은 **네 단계 모두에서** 제외한다.

M2-V2 와 M2-V3 는 **변수 개수가 2개로 같다.** 그래야 차이를 "변수를 더 넣어서"가
아니라 **"같은 개수의 변수를 다르게 정의해서"** 라고 말할 수 있다.

V3 에서 **새 모델 계열을 추가하지 않았다** — Best-CV 후보군은 Demo V2 와 동일하다.

## 10. 사건 압력 V3

`docs/event_method_v3.md` 참조. 요점:

- 사건을 **사안(episode) + 상태 변화(transition)** 두 층으로 기록
- 각 상태를 **직접성 · 범위 · 확실성**으로 채점 (확실성은 단계로부터 자동 결정)
- 시간이 지나면 **감쇠 + 잔존 하한** — 오래된 조치는 압력이 아니라 baseline
- 사안 안에서는 최댓값(중복 통제), 분류 안에서도 최댓값(같은 채널),
  분류 사이에서만 독립 증거로 결합 → 빈 분류가 신호를 희석하지 않음
- `PEP, NEP ∈ [0,1]` → **표준화하지 않음**
- 채점 규칙과 사건 목록을 **예측을 한 번도 실행하기 전에** 고정

## 11. 사건 기여 진단

`M2 − M1` 은 두 경로가 섞인 값이므로 counterfactual 로 분해한다.

```
직접  =  M2 예측  −  M2 예측(사건 변수를 0 으로)
간접  =  M2 예측(사건=0)  −  M1 예측
```

간접 경로는 변수가 2개 늘면서 나머지 모든 계수가 다시 적합되고, 교차검증이 다른
정규화 강도를 고르는 데서 나온다.

**측정 결과 두 효과가 비슷한 크기로 서로 상쇄되고 있었다.** 그래서 현재 설계로는
관측된 `M2 − M1` 차이를 사건 정보의 효과라고 부를 수 없다. 다음 사전등록에서
정규화 강도를 단계 간에 고정해 이 교란을 제거한다.

## 12. 결과 (있는 그대로)

사건 압력은 M1 을 개선하지 못했고 M1 도 M0 를 개선하지 못했다. 어느 비교도
통계적으로 유의하지 않다. 이 조건에서 가장 정확한 것은 여전히 M0 다.
`docs/findings_v3.md` 참조.

## 13. Demo V4 — Staged Residual Architecture

방법론은 실행 **전에** 설정 파일과 문서로 고정해 커밋했고,
실행은 **정확히 한 번**이다. 결과를 본 뒤 어떤 설정도 바꾸지 않았다.

### 13-1. 구조

```
M0            base layer (공식 M0 와 동일 규칙 · 예측값도 일치)
M1-R = M0   + market correction    (기존 12개 파생 시장 변수만)
M2-R = M1-R + event correction     (V3 PEP/NEP · 정의 불변)
```

**`M2-R − M1-R` 은 정의상 정확히 Event 보정폭이다.** 자동 테스트가 모든 예측
시점에서 이 항등식을 강제한다. 규제 재선택·전체 계수 재적합이 끼어들 자리가 없다.

### 13-2. Prequential 잔차 — in-sample 잔차 금지

보정 층의 학습 target 은 historically valid 해야 한다. 전체 학습행에 적합한 뒤 얻은
잔차를 쓰면 **실제 예측 시점에 관측 불가능한 값**을 배우게 된다.

각 예측 시점의 학습 구간 **안에서** expanding block 으로 만든다.

```
행: 대상월 오름차순 0 .. N
|<-- 초기 24행 -->|[ 6 ][ 6 ][ 6 ] ...
블록 [s,e):  [0,s) 에 적합 -> [s,e) 예측 -> 잔차
```

전처리(결측 대체·표준화)도 **각 블록의 적합 구간에만** fit 한다.
학습행 72 에서 base 잔차 48행 / event 잔차 24행, 118 에서 94행 / 70행이 나온다.

**명시적 한계.** 블록 재적합은 계수만 다시 추정하고 규제 강도·모델 family·성분 수는
그 시점의 학습 전체에서 고른 값을 쓴다. 블록 하나로는 내부 교차검증을 다시 만들 수
없기 때문이다. 모든 값이 `release_date <= O` 안에 있으므로 누수는 아니지만,
학습 구간 내부의 완벽한 실시간 모사도 아니다.

### 13-3. 후보 집합 (실행 전 동결)

| 층 | 후보 |
|---|---|
| Market correction | Ridge(6 alpha) · ElasticNet(4 alpha, l1=0.5) · **PLS(1~4 성분)** · Bayesian Ridge |
| Event feature | **E0** 수준 · **E1** 수준+변화 · **E2** 수준+1개월 lag |
| Event correction | OLS · Ridge(6 alpha) · Huber(ε=1.35) |

부호 제약 모델은 **도입하지 않았다** — 사전 신념을 모델에 넣는 것이 이번 단계의
질문과 어긋나기 때문이며, 이 결정은 성능을 보기 전에 내렸다.

선택은 전부 **학습 데이터 내부 시간순 교차검증**으로만 하고, 최종 Test 월은
어떤 선택에도 참여하지 않는다.

### 13-4. VIEW C — shared-alpha 대조

규제 재선택 교란을 제거한 joint Ridge 대조군. 예측 시점마다 **M1 학습에서 고른
규제 강도**를 구하고 그 **같은 값**을 M1 과 M2 양쪽에 적용한다.
따라서 `M1-shared` 는 공식 M1 과 일치한다.

### 13-5. 결과 (있는 그대로)

| 모델 | MAE |
|---|---|
| M0 | **49.19** |
| M1 | 50.75 |
| M2-V2 / M2-V3 | 50.72 / 51.61 |
| M1-shared / M2-shared | 50.75 / **50.90** |
| M1-R / M2-R | 60.99 / 67.40 |

- **V3 악화의 약 83% 는 Event 정보가 아니라 규제 재선택·재적합 교란이었다.**
  규제를 고정하면 Event 추가 비용은 MAE +0.149 로 통계적으로 구분되지 않는다.
- 단계 구조에서 Event 보정폭은 중앙값 0.20 → **15.17** 로 커졌다(|보정|>5 인 시점
  80%). **규제가 Event 신호를 억누르고 있었던 것은 사실이다** — 유계 변수는 같은
  기여를 만들려면 계수가 4.6배 커야 하고 벌점은 21배를 치른다(측정값).
- 그러나 방향 적중률은 **54%**, MAE 는 **+6.41** 악화됐다. 큰 보정 × 무작위 방향은
  분산 주입이다.
- 실패 원인(측정): prequential base 잔차 MAE **59.64** vs 최종 M0 실제 오차 **49.19**.
  보정 층이 약한 모델의 잔차 크기를 배워 강한 모델 위에 얹는다. 시장 보정은 오차의
  83% 크기인데 부호 적중은 42% 로 동전 던지기보다 나쁘다.

`docs/findings_v4.md` 참조. **가장 큰 남은 제약은 모델이 아니라 표본 크기다.**
