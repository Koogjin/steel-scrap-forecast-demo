## 0. 왜 여기로 왔나

V1~V7 은 여덟 가지 예측 대상에서 Event 의 증분 가치를 찾지 못했습니다. 더 중요한
것은 **같은 제약이 매 단계 다른 얼굴로 반복됐다**는 사실입니다.

| 단계 | 같은 제약이 나타난 모습 |
|---|---|
| V5 | 예측 대상과 **아무 관계 없는 난수**조차 내부검증을 중앙값 1.6%(시장)·5.6%(Event) "개선" |
| V6 | Event 를 포함한 모델만 **학습–실제 정확도 격차 +0.07 ~ +0.24** |
| V7 | 80% 구간이 **100% 과대커버** · 급등 사례 **4건**뿐 |

셋은 서로 다른 모형 문제가 아니라 **하나의 표본 문제**입니다.

- 예측 시점 **50개**
- 내부 검증 **3 fold × 12개월 = 36개월**
- 학습행 **72 ~ 118행**
- 예측오차 분포가 **시간에 따라 변함** (2021~22 격변기 + 2023~25 잔잔한 구간)

**새 Event feature 도 새 모형도 이 넷을 동시에 풀지 못합니다. 더 긴 Point-in-Time
이력만이 풉니다.**

## 2. 무엇을 조사할 것인가

### 2-1. Target 의 발표 이력을 얼마나 뒤로 늘릴 수 있나

BLS 의 공식 발간물 아카이브가 2015-02 이전 어느 시점까지 **날짜가 찍힌 원문**으로
남아 있는지 확인합니다. 이미 만들어 둔 파서와 발표일 추출기를 재사용합니다.

**판정 기준:** 원문에서 관측월과 발표일을 **둘 다** 뽑을 수 있어야 합니다.
못 뽑으면 그 구간은 포기합니다 — **추정하지 않습니다.**

### 2-2. 시장 변수 6종 중 어디까지 늘릴 수 있나

| 계열 | 전망 |
|---|---|
| 철강제품 PPI · 전력 PPI | target 과 **같은 병목** — 함께 늘거나 함께 막힙니다 |
| 제조업 주당근로시간 | 원기관 뉴스릴리스 아카이브가 더 깊음 — **유망** |
| 산업생산 · 1차금속 생산 · 가동률 | 연준 아카이브가 깊음 — **유망** |

### 2-3. 사건 기록을 **같은 규칙으로** 늘릴 수 있나

현재 첫 사건 기록은 2015-06 로, target 시작보다 늦습니다. **동일한 공식 출처
규칙**(정부 1차 출처 · 알려진 시점 기록 · 사후 소급 금지)을 그대로 적용해 앞 구간을
채울 수 있는지 확인합니다.

**이것은 "성능을 위해 사건을 더 캐는" 것이 아닙니다.** 표본 확장은 **모든 모델의
창을 동시에 넓히는** 작업이며, Event 분석은 그 뒤에도 **동결 상태로 둡니다.**

### 2-4. 예측 시점이 몇 개 늘어나는가

| target 시작을 앞당기면 | 예상 예측 시점 수 |
|---|---|
| 현재 (2014-09) | **50** |
| −12개월 | 약 **62** |
| −24개월 | 약 **74** |
| −36개월 | 약 **86** |

target 을 1개월 앞당길 때마다 예측 시점이 약 1개 늘어납니다. **취득 가능성을
확인하기 전에는 계획값일 뿐입니다.**

### 2-5. 내부 검증 표본 이득

| 학습행 | 가능한 설정 | 내부 검증월 |
|---|---|---|
| 72 ~ 118 (현재) | 3 fold × 12개월 | 36 |
| 120 ~ 150 | 4 × 12 | 48 |
| 150 이상 | **5 × 12 (원래 설계)** | **60** |

내부 검증 fold 를 5개에서 3개로 줄인 것은 성능 때문이 아니라 **산술적으로
불가능해서**였습니다. 표본이 늘면 **원래 설계로 되돌릴 수 있습니다.**

### 2-6. 검정력은 얼마나 좋아지나 (정직하게)

| 예측 시점 | 대략적 표준오차 | 탐지 가능한 최소 효과 |
|---|---|---|
| 50 (현재) | ±0.071 | 약 0.20 |
| 74 | ±0.058 | 약 0.16 |
| 86 | ±0.054 | 약 0.15 |

**주의:** 74개로 늘려도 V6 에서 관측된 효과 크기(−0.036)를 탐지할 검정력은 없습니다.

표본 확장은 **"Event 를 살리기 위한 것"이 아니라, 시장 정보에서 실제로 보인 개선
(통제 실험 +4.2%)을 확증하기 위한 것**으로 보는 편이 정직합니다.

## 4. 권장 순서

1. **취득 가능성 조사만** — 각 원기관 아카이브가 어디까지 날짜 찍힌 원문으로
   남아 있는지 확인. 데이터 저장 없음.
2. **확장 가능한 창을 확정하고 동결** — 성능을 한 번도 계산하지 않은 상태에서.
3. **기존 동결 방법론을 넓어진 창에서 그대로 재실행** — Event 는 건드리지 않음.
4. **그 결과를 보고** Event 를 다시 열지 말지 판단.
