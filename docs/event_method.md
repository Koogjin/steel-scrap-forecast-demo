# 공식 사건 압력 (PEP / NEP) — V2 방법론

> **EXPLORATORY EXTENSION.** 사전등록된 primary 결과가 아니다.

## 1. 무엇을 수집하지 않는가

- 뉴스 기사 본문을 수집·저장·재배포하지 않는다
- 뉴스 감성분석 API 를 쓰지 않는다
- 기사 수·토픽 수 같은 파생 지표를 만들지 않는다

모든 근거는 **공식 기관 문서 URL** 을 가리킨다. 기사가 후보 사건을 찾는 데 쓰였더라도
registry 의 증거는 반드시 official source 다.

## 2. V1 이 왜 실패했고 V2 가 무엇을 고쳤나

V1(9개 점 사건, 전부 2022-03 이후)의 M2 는 M1 보다 **22% 나빴다**. 원인은 측정으로
특정했다.

```
V1 압력 패널 231개월 중 비영(非零)  20개월
첫 origin 학습 74개월 중 비영        0.0%
마지막 origin 학습 123개월 중 비영   16.3%
```

학습 구간 대부분에서 상수 0 인 열을 `StandardScaler` 에 통과시키면 표준편차가 0 에
수렴하고, live 값이 극단적 z 로 폭발한다. 이것은 Phase 3C-V1 의 뉴스 feature 에서
이미 겪은 train/serve skew 와 같은 형태다.

**V2 는 두 가지를 모두 고친다.**

| 문제 | V1 | V2 |
|---|---|---|
| support | 점 사건만, 2022-03~ | POINT + **ONGOING 상태**, 2016-07~ |
| scaling | StandardScaler 적용 | **정의상 [0,1] 이라 표준화하지 않음** |

## 3. POINT 와 ONGOING

월을 채우려고 사건을 발명하지 않는다(§8). 대신 사건의 **성질**을 구분한다.

```
POINT    특정 시점의 발표/행동.  알려진 달 + 2개월 활성.
         예) 관세 포고 발표, 군사 타격, 비상사태 종료 선언

ONGOING  한 번 시작되면 종료 전까지 유효한 상태.
         예) 관세 부과 상태, 제재 상태, 분쟁 상태, 팬데믹 비상사태
```

그래서 굵직한 사건 하나가 여러 해에 걸쳐 의미 있는 상태를 만든다.
실제로 relevant state 가 없는 달은 **0 이어도 된다** — V2 의 첫 9개월
(2015-11 ~ 2016-07)이 그렇고, 그대로 둔다.

## 4. 카테고리 상태와 상한

고정 taxonomy `K = 6` 개 카테고리를 쓴다.

```
GEOPOLITICAL_CONFLICT · TRADE_TARIFF_SANCTION · ENERGY_SUPPLY
SHIPPING_LOGISTICS · PANDEMIC_EMERGENCY · INDUSTRIAL_SUPPLY_DEMAND
```

카테고리 `c`, 월 `m` 에 대해

```
up_c(m)   = max( 활성 사건의 upward_pressure_score )     (없으면 0)
down_c(m) = max( 활성 사건의 downward_pressure_score )   (없으면 0)
```

**`max` 를 쓰는 이유**: 같은 카테고리에 비슷한 사건이 5개 있다고 해서 그 달이
기계적으로 5배가 되면 안 된다. 상한이 없으면 "많이 수집한 달"이 자동으로 강한
신호가 되어 버린다.

> `INDUSTRIAL_SUPPLY_DEMAND` 는 현재 **적격 공식 기록이 없어 항상 0** 이다.
> 자리를 채우려고 사건을 만들지 않았고, taxonomy 는 결과에 따라 바꾸지 않는다.

## 5. 유계 PEP / NEP

```
PEP(m) = mean_c( up_c(m) / 3 )      ∈ [0, 1]
NEP(m) = mean_c( down_c(m) / 3 )    ∈ [0, 1]
```

이 정의가 좋은 이유:

- 의미가 안정적이다 (0 = 해당 압력 없음, 1 = 모든 카테고리가 최대)
- **유계**라 z-score 폭발이 원천적으로 불가능하다
- 시간에 걸쳐 비교 가능하다
- **수집한 사건 개수에 의존하지 않는다**

PEP 와 NEP 는 **독립**이며 합이 1일 필요가 없다.

```
low / low    조용한 환경
high / low   상승 압력 우세
low / high   하락 압력 우세
high / high  상충 환경   (예: 관세 — 국내가 상승 + 수입·전방수요 위축)
```

## 6. 스케일링 규칙

```
연속형 시장/이력 변수  ->  학습행에만 fit 하는 StandardScaler
PEP / NEP             ->  표준화하지 않는다 (이미 [0,1])
트리 계열 모델         ->  스케일링 불필요
```

테스트가 이를 강제한다: 선형 파이프라인의 `ColumnTransformer` 에서 `PEP`/`NEP` 가
스케일러를 거치는 분기에 포함되면 실패한다.

## 7. PIT 규칙

forecast origin `O` 는 대상월 `m` 의 **직전 월말**이다. 따라서 `m` 의 압력은
`m` 이 시작되기 전에 공식적으로 알려진 것만 쓴다.

```
정보월 = m - 1
활성 조건: known_at 월 <= 정보월
    ONGOING : start 월 <= 정보월 이고 (end 없음 또는 정보월 <= end 월)
    POINT   : 0 <= 정보월 - known_at 월 < 3
```

`known_at` 이 미래인 사건은 구조적으로 활성이 될 수 없다. registry 로더는
`known_at_date > backtest_last_origin` 인 기록을 **로드 단계에서 거부**한다 —
평가창(2025-12-31) 이후 사건이 backtest 에 들어올 수 없다.

## 8. 선정 규칙 — target 을 보지 않는다

```
금지: WPU1012 차트를 보고 사건을 고르기
금지: 예측오차를 보고 점수를 정하기
금지: MAE 를 본 뒤 사건 지속기간을 바꾸기
금지: 가격이 다르게 움직였다고 PEP/NEP 방향을 바꾸기
```

선정 기준은 세 가지뿐이다: 사전 정의된 category 에 속하는가 · 공식 문서로 확인되는가 ·
당시 알려져 있던 economic channel 이 철·강 스크랩과 연결되는가.

builder 모듈에는 target 패널 경로도 값 컬럼도 없으며, 테스트가 AST 로 이를 강제한다.

## 9. 환율을 사건으로 넣지 않는 이유

"달러 강세" 같은 환율 움직임은 **연속적인 시장 변수**이지 사건 라벨이 아니다.
사건으로 인코딩하면 임의의 임계값과 방향 판단이 들어간다. 환율·달러지수는 향후
별도의 **market feature extension** 으로 검토한다.
